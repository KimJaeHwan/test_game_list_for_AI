# 02. EMBERWARD: 마지막 봉화

화면 프레임만 보는 AI가 키보드로 짧은 액션 RPG를 끝까지 조작할 수 있는지 평가하는 로컬 테스트 게임입니다. 수호자의 지시를 기억하고, 숲과 폐허를 탐색한 뒤, 보스의 연속 예고에 맞춰 이동·방어·공격·룬을 사용해 마지막 봉화를 켜는 것이 목표입니다.

## 주요 기능

- 마우스 게임 입력 없이 방향키, `Enter`, `Space`, `Shift`, `1`만 사용하는 키보드 조작
- 60Hz 고정 틱으로 움직이는 실시간 게임 엔진과 연속 애니메이션
- 대화 단서, 넓은 숲 탐색, 문양 선택, 순서 기억, 룬 메뉴, 예고형 보스 전투로 이어지는 7단계 임무
- 콘텐츠 시드에 따른 정답 불씨, 벽화 순서, 약점 룬, 보스 패턴과 아이템 위치 변화
- 게임 규칙과 분리된 3종 비주얼 변형
- 실시간 트랙과 입력 단위 진단용 Sync 트랙
- 공격 궤적, 지속 방어막, 룬 폭발을 통한 즉각적인 키 입력 피드백
- 게임 시작 전 한 번만 표시되는 조작 브리핑과 전투 중 텍스트 힌트를 제거한 시각 패턴 평가
- 180초 제한, 120초 목표 시간, 1회 부활을 포함한 오류 복구
- 진행도, 예고 대응률, 체력, 시간 효율, 키보드 제어, 기억력, VCS 종합 점수
- 키 누름·해제 시점, 장면 전환, 판정 결과, 최종 상태 해시가 포함된 JSON 리플레이 내보내기
- 완료 기록을 브라우저 `localStorage`에 최대 20개 저장

## 게임 진행

1. 수호자의 대화에서 가져올 불씨 문양과 보스의 약점 룬을 확인합니다.
2. 숲을 이동해 여러 후보 중 지시와 같은 불씨를 집습니다.
3. 폐허의 벽화를 조사하고 표시된 문양 순서를 기억합니다.
4. 제단에서 같은 순서로 문양을 입력합니다.
5. 룬 메뉴에서 앞서 들은 약점 룬을 장착합니다.
6. 보스의 예고를 연속으로 관찰해 공격, 룬, 방어 유지, 회피 이동으로 대응합니다.
7. 보스를 쓰러뜨린 뒤 봉화에 접근해 불을 켭니다.

잘못된 불씨·문양·룬 선택은 감점되지만 즉시 실패하지 않습니다. 전투에서도 한 번은 부활하므로, AI가 실패 결과를 읽고 전략을 수정하는 능력까지 관찰할 수 있습니다.

## 조작법

| 키 | 동작 |
| --- | --- |
| `↑` `↓` `←` `→` | 이동, 메뉴 및 문양 선택 |
| `Enter` | 대화 진행, 조사, 선택 확정, 봉화 점화 |
| `Space` | 보스의 빈틈에 공격 |
| `Shift` 유지 | 충격파 방어 |
| `1` | 장착한 룬 사용 |
| `Esc` | 타이틀로 돌아가기 |

게임 도중 브라우저 포커스를 잃으면 자동으로 일시 정지합니다. 화면을 다시 활성화하고 `Enter`를 눌러 계속할 수 있습니다.

## AI 조작 평가에 적합한 이유

클릭형 정적 UI는 한 장의 화면을 해석하고 한 지점을 누르는 능력에 치우치기 쉽습니다. EMBERWARD는 프레임이 계속 바뀌는 상황에서 다음 폐쇄 루프 전체를 요구합니다.

```text
연속 화면 관찰 → 지시·예고 해석 → 키 선택 → 누름/유지/해제
→ 이동·전투 결과 확인 → 기억 갱신 → 오류 복구
```

- **지각**: 플레이어, 장애물, 상호작용 표식, 서로 다른 문양과 전투 예고를 구분해야 합니다.
- **시간 제어**: 이동과 방어는 키를 일정 시간 유지한 뒤 정확히 해제해야 하며, 공격과 룬은 제한된 예고 시간 안에 입력해야 합니다.
- **기억**: 초반 대화의 불씨와 약점, 잠시 공개되는 벽화 순서를 뒤 장면에서 재사용해야 합니다.
- **공간 계획**: 넓은 횡스크롤 숲과 여러 방에서 충돌을 피하며 목표까지 이동해야 합니다.
- **문맥 전환**: 같은 방향키와 `Enter`가 이동, 대화, 선택 메뉴, 제단 입력에서 서로 다른 의미를 갖습니다.
- **복구**: 오답과 피격 뒤에도 화면 피드백을 읽고 임무를 계속할 수 있습니다.
- **재현성**: 같은 시드와 같은 입력 로그는 같은 최종 상태 해시를 만들기 때문에 모델 비교와 회귀 검사가 가능합니다.

단순 성공 여부 외에도 불필요한 키 입력, 벽 충돌 시간, 오답, 피격, 예고 대응률을 따로 기록하므로 “우연히 클리어한 실행”과 “안정적으로 이해하고 조작한 실행”을 구분할 수 있습니다.

## 평가 프로토콜

권장 관찰 입력은 게임의 `960 × 540` 캔버스만 잘라 `640 × 360`, 15 FPS의 래스터 프레임으로 전달하는 방식입니다. AI에는 DOM, 접근성 트리, 자바스크립트 상태, 네트워크 로그를 제공하지 않습니다. 페이지 오른쪽의 진행도와 상태 해시는 사람 평가자를 위한 계측 패널이므로 공식 에이전트 관찰 영역에서 반드시 제외해야 합니다.

권장 트랙은 다음과 같습니다.

| 트랙 | 용도 |
| --- | --- |
| Realtime | 실제 시간에 계속 진행되는 기본 평가. 지연, 연속 추적, 키 유지·해제를 함께 측정합니다. |
| Sync | 입력이 있을 때 고정 틱 묶음으로 진행되는 로컬 진단 모드. 인식·행동 오류와 통신 지연의 영향을 분리할 때 사용합니다. |

공정한 비교에서는 모델별로 같은 콘텐츠 시드와 비주얼 변형을 사용하고, 시드 목록은 평가가 끝날 때까지 숨기는 것을 권장합니다. 현재 MVP는 콘텐츠 시드와 비주얼 변형을 지원하며, 프레임 드롭·지연 같은 전송 환경 난수는 외부 평가 하네스에서 주입해야 합니다.

## 점수

VCS(Visual Control Score)는 다음 요소를 합산한 0~100점 지표입니다.

```text
VCS = 60% 임무 진행도
    + 20% 보스 예고 대응률
    + 10% 진행도 × 남은 체력
    + 10% 목표 시간 효율
    - 오답·피격 페널티
```

보조 지표로 벽 충돌과 무효 입력을 반영한 **키보드 제어 점수**, 제단 오답과 잘못된 룬 선택을 반영한 **기억력 점수**를 함께 제공합니다. 총점만 단독으로 사용하기보다 JSON 리플레이의 장면별 입력과 판정 이벤트를 함께 분석하는 것이 좋습니다.

## 로컬 실행

Node.js 22.13 이상과 pnpm이 필요합니다.

```bash
cd 02_emberward
pnpm install
pnpm dev
```

브라우저에서 `http://localhost:3001`을 엽니다. 01 게임과 동시에 실행할 수 있도록 기본 포트를 3001로 지정했습니다.

## 검증

```bash
pnpm verify:game
pnpm build
```

`verify:game`은 20개 시드의 완주 가능성, 동일 입력 리플레이의 상태 해시 일치, 시드별 콘텐츠 변화, 오답 뒤 복구를 검사합니다. `build`는 TypeScript 타입 검사와 Vite 프로덕션 번들 생성을 수행합니다.

## 현재 범위

이 버전은 로컬 단일 플레이 평가용 MVP입니다. 오디오 단서, 서버 순위표, 프레임 전송기, 입력 지연·프레임 드롭 시뮬레이터는 포함하지 않습니다. JSON 파일과 `localStorage`는 평가 결과 보관용이며 게임 진행에 필요한 정답을 제공하지 않습니다.
