# QUEST ATLAS 평가 프로토콜

## 평가 질문

이 벤치마크는 다음 질문에 답합니다.

> 화면만 본 AI가 플레이 경험을 근거로 게임 콘텐츠의 개체·관계·조건·절차·예외를 정확히 구조화하고, 그 지식으로 동일 콘텐츠를 재현하거나 다른 배치에 전이할 수 있는가?

완주 시간, 초당 입력 수, 전투 반응 속도는 콘텐츠 이해 점수에 포함하지 않습니다. 행동 수는 이미 목표를 달성한 실행 안에서 절차 효율을 비교할 때만 보조적으로 사용합니다.

## 권장 실험 절차

1. 고정한 `scenarioSeed`와 임의의 `layoutSeed`, `visualSeed`, `sessionSeed`로 탐색 세션을 시작합니다.
2. 에이전트에는 게임 캔버스 이미지와 허용 키 입력만 제공합니다.
3. 에이전트가 자유 탐색을 끝내면 결과 화면에서 세션 패키지를 내보냅니다.
4. 에이전트는 관찰 원문의 `OBS-...` 번호를 근거로 `knowledge.json`과 `WIKI.md`를 작성합니다.
5. 새 상태의 같은 시드에서 제출 절차로 비공개 목표를 실행해 재현 점수를 기록합니다.
6. `scenarioSeed`만 유지하고 나머지 세 시드를 바꿔 별도 에이전트에 위키만 제공합니다.
7. 전이 실행 결과와 지식 제출물을 평가 모듈에 전달합니다.

훈련·평가 누출을 피하려면 `src/content`, 생성된 월드 객체, 내부 근거 큐, 정답 사실 그래프를 플레이 에이전트에게 제공하면 안 됩니다.

플레이 화면과 공개 세션에는 원본 시드·시나리오 해시를 표시하지 않습니다. 단, 정적 웹 번들에는 게임 실행에 필요한 콘텐츠가 포함되므로 DOM·개발자 도구·네트워크·소스 접근 권한을 가진 에이전트는 공식 평가 대상이 아닙니다. 그런 권한까지 시험하려면 콘텐츠 생성과 정답 그래프를 별도 평가 서버로 이동해야 합니다.

## 지식 제출 단위

- `entities`: NPC, 지역, 아이템, 퀘스트 등 식별한 개체와 속성
- `claims`: `subject`, `predicate`, `object`, `conditions`로 표현한 원자적 사실
- `procedures`: 목표, 선행조건, 순서가 있는 행동, 예상 상태 변화, 대안, 실패·복구 방법
- `evidence`: 주장을 뒷받침하는 실제 관찰 번호 묶음과 설명
- `unknowns`: 확인하지 못한 내용을 추측하지 않고 남기는 목록
- `contradictions`: 소문과 관찰 결과처럼 충돌한 정보

각 주장과 절차에는 0~1의 신뢰도를 기록합니다. 현재 신뢰도 보정과 고신뢰 환각 패널티는 `claims`에 적용되며, 절차는 실제 엔진 재생의 성공·효율로 검증됩니다.

## 주장 표준 어휘

정답을 맞히려면 화면에 나온 한국어 이름을 그대로 사용하고 다음 `predicate`와 `object` 형태로 기록합니다. 이는 답을 공개하는 목록이 아니라 제출 형식의 온톨로지입니다.

| predicate | subject | object 요약 |
| --- | --- | --- |
| `연결` | 출발 지역 | 도착 지역 이름 |
| `퀘스트 절차` | 퀘스트 제목 | `{ "목표": [...], "보상": [...] }` |
| `획득처` | 아이템 이름 | `[{ "방식", "대상", "조건" }]` |
| `출현 및 획득` | 조우 이름 | `{ "획득": [...], "반복": true/false }` |
| `제작식` | 제작품 이름 | `{ "재료": [[대체재...]], "결과": [...] }` |
| `구매`, `교환` | 상점 이름 | `{ "비용": [...], "보상": [...] }` |
| `상태 전환`, `상태 변화` | 화면에 나온 대상 | 상태 또는 값 |
| `상호 배타`, `보상` | 계약·진영 | 선택지 또는 보상 |
| `소문`, `검증 결과` | 소문 내용 | 주장 또는 관찰된 교정 내용 |
| `필수 접합재`, `필요 아이템`, `필수 촉매` | 제작·조우 대상 | 화면에 나온 아이템 이름 |

아이템 묶음은 `{ "아이템": "이름", "수량": 숫자 }`이고, 조건은 `{ "종류": "아이템 보유|퀘스트 상태|세계 상태|시간|조수|계약|소문 확인", ... }` 형태입니다. 실제 필드 예시는 내보낸 `knowledge.json`의 예시 항목과 `src/eval/world-adapter.ts` 계약을 기준으로 합니다.

## 100점 구성

| 항목 | 배점 | 측정 내용 |
| --- | ---: | --- |
| 사실 정확도 | 35 | 가중 정밀도·재현율의 F1 |
| 발견 가능 사실 완전성 | 15 | 실제 플레이로 확인 가능한 정답 중 찾아낸 비율 |
| 동일 시드 재현 | 15 | 작성 절차의 목표 달성도와 행동 효율 |
| 다른 배치 전이 | 20 | 동일 규칙·새 배치에서 위키만으로 달성한 정도 |
| 근거·신뢰도 | 10 | 유효한 OBS 인용, 근거 범위, 신뢰도 보정 |
| 위키 준비도 | 5 | 스키마 유효성, 엔티티·주장·절차·근거 구성 |

지원되지 않은 주장과 조건 불일치에는 환각 패널티가 추가되며 최대 25점까지 차감됩니다. 기본 오탐 가중치는 1.5배이고, 신뢰도 0.8 이상의 오탐은 다시 1.5배로 계산됩니다.

## 비교 실험 예시

- **지각 유지성**: 같은 규칙에서 `visualSeed`만 바꿔 아이콘·색 변화에 견디는지 확인
- **공간 표현 독립성**: `layoutSeed`만 바꿔 문서가 좌표를 외운 것인지 관계를 배운 것인지 확인
- **세션 상태 추론**: `sessionSeed`만 바꿔 시작 시각·조수가 달라도 조건을 적용하는지 확인
- **규칙 일반화**: 탐색과 평가에 다른 `scenarioSeed`를 사용해 새 조건을 다시 조사하는 능력 측정
- **문서 유용성**: 플레이 에이전트 A가 쓴 위키로 에이전트 B가 목표를 수행하게 하여 개인 기억과 문서 품질 분리
- **소문 검증**: 대화 정보와 실제 행동 결과가 충돌할 때 `contradictions`에 기록하고 단정하지 않는지 확인

## 자동 검증 기준

- 동일 설정은 바이트 수준으로 같은 월드를 생성한다.
- 비시나리오 시드 변경은 규칙 그래프 해시를 바꾸지 않는다.
- 최소 50개 혼합 시드가 참조 무결성 검사를 통과한다.
- 최소 16개 시나리오가 공식 엔진 입력만으로 메인 콘텐츠를 완주한다.
- 완주 행동 로그를 재생하면 최종 상태 해시가 일치한다.
- 공개 세션 JSON은 `cueId`, `factIds`, 내부 source/region ID와 이벤트 상세를 포함하지 않는다.
- 평가 회귀군에서 누락·환각·조건 오류·무효 근거·낮은 실행 성능이 각각 정답 제출보다 낮은 점수를 받는다.

## 평가기 통합

평가자는 같은 신뢰 프로세스에서 다음 순서로 API를 사용합니다.

1. `canonicalFactsFromWorld(world)`로 비공개 월드 정답을 한국어 제출 어휘로 변환합니다.
2. 탐색 종료 직전의 내부 `GameState`를 `evaluationContextFromState(state)`에 전달해 현재 RUN의 근거와 실제 발견 fact 집합을 만듭니다.
3. 재현·전이 에이전트가 낸 키 행동 로그를 `runVerifiedReplay(...)`로 새 월드에 재생합니다.
4. 위 결과와 제출 `knowledge.json`을 `evaluateSubmission(...)`에 함께 전달합니다.

재현은 네 시드가 모두 같아야 하고, 전이는 같은 시나리오 규칙을 유지하면서 layout·visual·session 중 하나 이상이 달라야 합니다. 호출자가 직접 만든 실행 결과, JSON으로 복제한 결과, 제출에 없는 procedure ID의 결과는 거부됩니다. 이 검증 표식은 프로세스 메모리에만 존재하므로 분산 평가에서는 서버 서명 방식으로 교체해야 합니다.
