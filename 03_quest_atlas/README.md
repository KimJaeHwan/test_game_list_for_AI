# 03. QUEST ATLAS: 안개항 조사록

AI가 게임을 **잘 조작하는지**보다, 직접 플레이하며 콘텐츠의 규칙을 발견하고 관계를 구조화해 재현 가능한 문서로 만드는지를 평가하는 키보드 전용 조사 RPG입니다.

## 게임 콘텐츠

플레이어는 안개항 조사관이 되어 여섯 지역을 탐색하고 봉화를 복구합니다. NPC 대화, 이동 조건, 시간·조수 변화, 채집, 상점·교환, 제작, 퀘스트 선후관계를 직접 확인해야 합니다.

- 지역 6개, NPC 12명
- 퀘스트 14개: 메인 6, 사이드 5, 숨은 2, 반복 1
- 아이템 29종, 조우·채집 7종, 제작식 7개
- 상점 3개와 거래 8개
- 상호 배타 분기, 조건부 예외, 그럴듯하지만 틀린 소문 3개
- 채점 가능한 사실 95개와 각각에 대응하는 관찰 근거 95개

전투 반사신경이나 정교한 이동은 요구하지 않습니다. 화살표로 현재 지역의 행동을 고르고 `Enter`로 실행하는 턴 방식입니다.

## AI 평가에 적합한 이유

이 게임은 단순 완주 점수와 콘텐츠 이해 점수를 분리합니다.

1. **발견**: 화면의 대화와 행동 결과에서 개체, 관계, 조건, 보상, 예외를 찾아야 합니다.
2. **근거화**: 모든 관찰에는 불투명한 `OBS-...` 번호가 붙습니다. AI는 주장마다 실제 관찰 번호를 인용해야 합니다.
3. **구조화**: 엔티티 목록뿐 아니라 `주체-관계-대상-조건`, 성공 절차, 실패 조건, 복구법을 `knowledge.json`에 기록합니다.
4. **재현**: 같은 시드를 초기화한 뒤 작성한 절차로 비공개 목표를 다시 달성합니다.
5. **전이**: 콘텐츠 규칙은 같고 배치·표현만 다른 시드에서 문서만 전달받은 별도 에이전트가 목표를 수행합니다.
6. **환각 억제**: 틀린 조건, 관찰되지 않은 고신뢰 주장, 근거가 맞지 않는 인용은 명시적으로 감점됩니다.

따라서 “화면을 보고 키를 잘 눌렀다”와 “게임의 콘텐츠 모델을 정확히 만들었다”를 구분해 볼 수 있습니다.

## 조작법

| 상황 | 키 | 기능 |
| --- | --- | --- |
| 시작/브리핑 | `Enter`, `←`, `→` | 시작, 이전·다음 안내 |
| 탐색 | 방향키 | 행동 대상 선택 |
| 탐색 | `Enter` | 선택한 이동·대화·채집·제작·거래 실행 |
| 탐색 | `C` | 퀘스트/가방/최근 관찰 패널 전환 |
| 조사록 | `Tab` | 조사록 열기·닫기 |
| 조사록 | 방향키 | 관찰 선택 |
| 조사록 | `B` 또는 `Enter` | 관찰 북마크 |
| 조사록 | `F` | 전체/북마크/관찰 유형 필터 |
| 결과 | `E` | 세션·지식 템플릿·위키 템플릿 내보내기 |
| 결과 | `R` | 동일 시드 다시 시작 |
| 결과 | `N` | 같은 규칙, 새 배치·표현·세션으로 시작 |

게임 중 포커스를 잃으면 입력이 자동 정지되며 `Enter`로 재개합니다. 공식 평가에서 AI가 관찰할 수 있는 영역은 1280×720 게임 캔버스뿐입니다. 개발자 도구, 소스, 네트워크 응답, 로컬 저장소는 관찰로 인정하지 않습니다.

## 시드

평가 운영자는 URL 쿼리로 네 종류의 난수를 독립 제어합니다. 플레이 캔버스와 공개 세션에는 원본 시드 대신 불투명한 RUN ID만 표시됩니다.

```text
http://localhost:3002/?scenario=7301&layout=11&visual=1&session=29
```

| 파라미터 | 바뀌는 것 |
| --- | --- |
| `scenario` | 제작 재료, 조수 조건, 보호 도구, 분기 보상 등 실제 규칙 |
| `layout` | 지역 좌표, 표시 순서와 방향 |
| `visual` | 팔레트와 아이콘 표현 |
| `session` | 시작 시각·조수와 날씨 표식 |

전이 평가는 `scenario`를 고정하고 나머지 값만 바꿉니다. 이때 규칙 그래프 해시는 유지됩니다.

## 실행과 검증

Node.js 22.13 이상과 pnpm이 필요합니다.

```bash
pnpm install
pnpm dev
```

브라우저에서 `http://localhost:3002/`를 엽니다.

```bash
pnpm build
pnpm verify
```

`verify:game`은 50개 생성 시드를 검사하고, 서로 다른 16개 시나리오와 양쪽 진영 분기를 실제 엔진 행동으로 끝까지 완주한 뒤 같은 행동 로그의 최종 상태 해시가 일치하는지 확인합니다. `verify:eval`은 실제 생성 월드·관찰·엔진 재생을 평가기에 연결하고, 누락, 환각, 잘못된 조건, 무효·과다·타 RUN 근거, 위조 실행 결과가 예상 방향으로 감점되는지 검사합니다.

## 결과 파일

완료 화면에서 `E`를 누르면 세 파일을 받습니다.

- `*-session.json`: 불투명 RUN ID, 상태 해시, 화면에서 확인한 관찰 원문, 공개 이벤트, 키 행동 로그
- `*-knowledge.json`: 엔티티·주장·절차·근거·미확인 사항을 작성하는 구조화 템플릿
- `*-WIKI.md`: 사람이 읽을 수 있는 위키 문서 템플릿

세션 파일에는 내부 사실 ID, 근거 큐 ID, 대화 분기 ID 같은 정답 메타데이터가 포함되지 않습니다. 자세한 실험 절차와 점수식은 [EVALUATION.md](./EVALUATION.md)를 참고하세요.

이 프로젝트는 로컬 정적 웹 앱이므로 JavaScript 파일 자체를 읽을 수 있는 에이전트에 대한 정답 격리는 보장하지 않습니다. 공식 이미지 기반 평가는 캔버스 픽셀과 키 입력만 중계하고 DOM, 개발자 도구, 네트워크 본문, 소스 파일 접근을 차단해야 합니다.

## 구조

```text
src/content/   시드 생성, 콘텐츠 카탈로그, 무결성 검사
src/engine/    상태, 규칙, 입력 리듀서, 공개 세션 생성
src/ui/        캔버스 셸과 렌더러
src/eval/      지식 스키마, 실제 월드 어댑터, 사실·근거·종합 채점
src/replay/    엔진 검증 동일 시드 재현 및 전이 실행 점수
scripts/       게임 완주와 평가 회귀 검증
```

설계 원칙과 모듈 분담은 [DESIGN.md](./DESIGN.md)에 기록되어 있습니다.
